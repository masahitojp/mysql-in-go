# 起動・終了時間の測定

2026-11-10、今回の Ubuntu 26.10 / Linux amd64 のホストで各ケースを 5 回ずつ逐次実行した。
MySQL 8.4.13 / Bao 組み込み版、InnoDB buffer pool 64 MiB、TCP 無効。
測定コードは [`cmd/startuptime/main.go`](../cmd/startuptime/main.go)。

| 測定対象 | 平均 | 最小〜最大 |
| --- | --- | --- |
| 新規 DB の `Start()`（初期化込み） | 1.720 秒 | 1.687〜1.757 秒 |
| 接続済み状態の `SELECT 1`（結果を Scan するまで） | 0.253 ms | 0.168〜0.362 ms |
| `Close()`（正常終了・子回収・一時データ削除まで） | 1.026 秒 | 0.999〜1.054 秒 |
| API 全体: Start → SELECT 1 → Close | 2.746 秒 | 2.734〜2.756 秒 |

別の 5 回では、データ初期化コマンドと、その後の API Start を分けて測定した。
初期化と API のデータ保存先はいずれも OS の一時ディレクトリ。

| 測定対象 | 平均 | 最小〜最大 |
| --- | --- | --- |
| `--initialize-insecure` による初期化 | 1.341 秒 | 1.337〜1.348 秒 |
| 初期化済みの空 DB から Start（接続成功まで） | 0.363 秒 | 0.352〜0.402 秒 |
| 上記の起動・SELECT 1・Close（初期化は除外） | 約 1.390 秒 | — |

Go のコンパイル時間は含めない。`Start()` は SQL 接続の成功を確認してから戻る。
現在の接続待ちのポーリング間隔は 50 ms のため、起動時間にはその待ちも含む。
後の確認で、このホストの `/tmp` は tmpfs と分かった。ディスク上の DB 初期化速度の測定ではない。
OS キャッシュの消去やホストの負荷隔離は行っておらず、コールド起動性能を保証する数字ではない。
DB サイズ、ストレージ、同時起動数、マシン負荷で結果は変わる。

## 再測定

リポジトリのルートで、サーバーをビルドした後に実行する。

```sh
make timing
```

測定用 Go プログラムだけをビルドし、各ケース 5 回ずつ実行する。
進捗は stderr、各サンプルのミリ秒値は JSON で stdout に出力する。
Go のビルド時間はサンプルに含めない。
測定データは一時ディレクトリに作成し、測定終了時に削除する。
既存のユーザーデータディレクトリは使わない。

今回の生データは `.work/startup-timing-matched.json`、進捗は `.work/startup-timing-matched.log` に保存した。
